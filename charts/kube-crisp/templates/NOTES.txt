Nothing is served yet. A projection is a cluster object, so create one:

  1. A Secret holding the connection string, in {{ include "kube-crisp.dataSourceNamespaces" . }},
{{- if .Values.crisp.requireDataSourceOptIn }}
     labelled crisp.kubecrisp.io/allow-projection=true so it may be used:
{{- else }}
     (the opt-in label is not required, since crisp.requireDataSourceOptIn is off):
{{- end }}

       kubectl create secret generic orders-db -n {{ include "kube-crisp.dataSourceNamespaces" . }} \
         --from-literal=dsn='postgres://user:pass@host:5432/store?sslmode=require'
{{- if .Values.crisp.requireDataSourceOptIn }}
       kubectl label secret orders-db -n {{ include "kube-crisp.dataSourceNamespaces" . }} \
         crisp.kubecrisp.io/allow-projection=true
{{- end }}

  2. A CustomResourceProjection describing the resource, the queries, and the
     mapping. See https://github.com/mrueg/kube-crisp for a worked example per
     driver, or ask the cluster:

       kubectl explain customresourceprojection.spec

  3. Watch it come up. {{ if .Values.crisp.manageAPIServices }}The APIService registers itself.{{ else }}crisp.manageAPIServices is off, so create the
     APIService for each projected group yourself.{{ end }}

       kubectl get customresourceprojections

networkPolicy.databaseEgress to bound where those connections may go.
